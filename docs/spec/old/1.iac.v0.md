# 🛠️ SPEC-01: Provisionamento de Infraestrutura via IaC (Slurm Cluster)

## 1. Visão Geral e Objetivos
* **Objetivo**: Subir e configurar de forma automatizada, idempotente e reprodutível um cluster heterogêneo gerenciado pelo **Slurm Workload Manager**, equipado com aceleração por GPU, banco de dados para contabilização (*accounting*) e armazenamento compartilhado (NAS).
* **Tecnologia Principal de IaC**: Ansible.
* **Ambiente Alvo**: Linux Ubuntu 24.04 LTS (ou equivalente).
* **Princípio Arquitetural**: O inventário do Ansible e as variáveis são a **única fonte da verdade** (*single source of truth*). NENHUM arquivo dentro de `/etc/slurm/` deve ser editado manualmente.

---

## 2. Componentes da Pilha Tecnológica (*Stack*)
1. **Autenticação Inter-Nós**: `munge` (chave simétrica em `/etc/munge/munge.key`).
2. **Gerenciador de Cargas (Slurm)**:
   * `slurmctld`: Daemon do nó controlador (fila central e alocação).
   * `slurmd`: Daemon dos nós de computação (*workers*).
   * `slurmdbd`: Daemon de contabilidade de histórico.
3. **Banco de Dados**: MariaDB (armazenamento persistente de histórico para `slurmdbd`).
4. **Armazenamento Compartilhado**: NAS via NFS montado no diretório dos experimentos/datasets.
5. **Isolamento de Recursos**: Kernel `cgroups` (para delimitar CPUs, memória e GPUs por job).

---

## 3. Estrutura do Repositório Ansible (`slurm-lab/`)

```text
slurm-lab/
├── ansible.cfg                 # Configurações padrão do Ansible (playbook_dir, etc.)
├── inventory/
│   └── hosts.yml               # Definição de hosts (controller vs compute) e hardware de host
├── group_vars/
│   └── all.yml                 # Variáveis globais do cluster (cluster_name, portas, etc.)
├── site.yml                    # Playbook principal de orquestração
└── roles/
    ├── base/                   # Instalação de pacotes base (slurm-wlm, slurm-client, etc.)
    ├── munge/                  # Distribuição da chave munge e gestão do serviço
    └── slurm/                  # Geração de templates Jinja2 e gestão de daemons (slurmctld/slurmd)
```

---

## 4. Requisitos de Configuração e Templates (Jinja2)

### 4.1. `slurm.conf.j2`
* **Identificação**:
  * `ClusterName={{ cluster_name }}`
  * `SlurmctldHost={{ controller_host }}`
  * `SlurmUser=slurm`
* **Políticas do Escalonador**:
  * `SchedulerType=sched/backfill` (permite preenchimento de lacunas).
  * `SelectType=select/cons_tres` (trata CPUs, RAM e GPUs como recursos consumíveis).
  * `SelectTypeParameters=CR_Core` (aloca núcleos físicos inteiros).
  * `GresTypes=gpu`.
* **Topologia de Nós e Partição**:
  * Laço dinâmico gerando as linhas `NodeName={{ h }} ... CPUs={{ hostvars[h].cpus }} RealMemory={{ hostvars[h].real_memory }} Gres=gpu:{{ hostvars[h].gpu_count }}`.
  * Partição `debug` cobrindo os nós de computação.

### 4.2. `gres.conf.j2`
* Para nós com GPU física real, mapear explicitamente os dispositivos do sistema operacional:
  ```jinja2
  NodeName={{ h }} Name=gpu File={{ hostvars[h].gpu_device }}
  ```

### 4.3. `cgroup.conf.j2`
* Habilitar restrições rigorosas de isolamento de hardware por job:
  ```ini
  CgroupPlugin=autodetect
  ConstrainCores=yes
  ConstrainRAMSpace=yes
  ConstrainDevices=yes
  ```

---

## 5. Fluxo de Execução do Playbook (`site.yml`)
1. **Role `base`**: Instala pacotes do sistema via `apt` (`slurm-wlm`, `slurm-client`, `munge`) e cria diretórios `/var/spool/slurmctld` (dono: `slurm`) e `/var/spool/slurmd` (dono: `root`).
2. **Role `munge`**: Copia a chave simétrica `munge.key` (permissão `0400`, dono `munge`) e garante o serviço ativo.
3. **Role `slurm`**: Renderiza os arquivos `slurm.conf`, `gres.conf` e `cgroup.conf`. Notifica os *handlers* para reiniciar os serviços (`slurmctld` no controlador e `slurmd` nos nós) apenas se a configuração for alterada (*idempotência*).

---

## 6. Critérios de Aceite e Validação (*Healthchecks*)
Para que a automação seja considerada finalizada com sucesso, os seguintes comandos devem retornar sem erros:

1. **Validação do Munge**:
   ```bash
   munge -n | unmunge
   ```
   *Resultado esperado*: `STATUS: Success (0)`.
2. **Validação de Nós e Partições no Slurm**:
   ```bash
   sinfo -N -l
   ```
   *Resultado esperado*: Todos os nós listados com estado `IDLE` (disponíveis).
3. **Checagem de Recursos Detectados pelo Slurm**:
   ```bash
   scontrol show node <hostname>
   ```
   *Resultado esperado*: Quantidade correta de CPUs, RealMemory e `Gres=gpu:X` declaradas.
4. **Teste de Alocação Real de GPU (PoC de Isolamento)**:
   ```bash
   srun --gres=gpu:1 nvidia-smi
   ```
   *Resultado esperado*: A GPU é listada com sucesso dentro da sessão do job.
